## What is in the box

| Piece | What it does |
|---|---|
| `createQuickBooks()` | Wires everything from one config object |
| OAuth | Authorize URL, callback parsing, code exchange, refresh, revoke; signed `state` for CSRF protection; realm id from the callback |
| `TokenStore` | Tiny `get/set/delete` interface. `MemoryTokenStore`, `FileTokenStore` (atomic, 0600), `SqliteTokenStore` (any `better-sqlite3` / `node:sqlite`-shaped handle) |
| `TokenManager` | Single-flight refresh, rotation persisted before use, adopts tokens another process already rotated, optional cross-process `lock` hook |
| `QboClient` | Find-or-create customer, sparse update, items and price map (paginated), estimate, estimate → invoice (with a double-invoice guard), sales receipt, record payment, raw `request()` / `query()` |
| Errors | `QboError` with the parsed `Fault`, `QboReconnectRequiredError`, `QboNotConnectedError` |
| Audit | `AuditLog` interface, memory and JSONL implementations, `summarizeHealth()` |
| `/next` | Web-standard `Request`/`Response` route handlers: connect, callback, status, test, disconnect, audit |
| `/react` | `<QboConnectionStatus />` and the presentational `<QboConnectionStatusView />` |
| `/testing` | `startFakeQbo()`: an in-process fake of Intuit's OAuth and the REST endpoints above |

## Install


## Bring your own keys

1. Sign in at developer.intuit.com and create an app with the **QuickBooks Online and Payments** scope `com.intuit.quickbooks.accounting`.
2. Under *Keys & credentials → Development*, copy the **Client ID** and **Client secret**.
3. Add a **Redirect URI** that exactly matches the one you pass to the kit, such as `http://localhost:3000/api/quickbooks/callback`.
4. A sandbox company is created for you under *Sandbox*. Intuit's production keys require completing its app assessment, which is outside this library.

Anything that is not exactly `production` / `prod` resolves to **sandbox**. Stored tokens remember the environment they were issued for and are ignored if you switch, so sandbox tokens are never sent to the other environment.

POSTs also reject a cross-origin `Origin` header, and the handlers never return tokens.

## API overview

- **Customers:** `findOrCreateCustomer`, `findCustomerByEmail`, `findCustomerByDisplayName`; `findOrCreateCustomer` also sparse-updates an existing customer.
- **Items:** `buildPriceMap()` returns `{ 'Name': { id, unitPrice, … } }`; `findItemByName`.
- **Documents:** `createEstimate`, `convertEstimateToInvoice` (throws `ALREADY_INVOICED` on repeat), `createSalesReceipt`, `recordPayment`.
- **Escape hatches:** `request()`, `query()` and `qboQuote()` for values interpolated into queries.
- **Kit methods:** `connectUrl()`, `handleCallback()`, `status()`, `testConnection()`, `disconnect()`, `health()`.

## Design notes

- **Token refresh.** Intuit rotates refresh tokens, so two concurrent refreshes with the same old token would race. The kit coalesces callers in one process, writes new tokens to the store before returning them, and if Intuit answers `invalid_grant` while the store already holds a newer token it adopts that. For multiple instances add the `lock` option (a database advisory lock, Redis lock, …).
- **401 handling.** One forced refresh, one retry. 429 and GET 5xx retry with `Retry-After` and backoff. POSTs are never blindly retried on 5xx, and every create carries a `requestid`.
- **Audit log.** Every client call, refresh and connection action records action, outcome, duration, status, `intuit_tid` and the QBO ids touched. Tokens and request bodies are never recorded; keep PII and secrets out of your own `metadata`.
- **Token storage.** Tokens are stored as plain JSON. Use disk or volume encryption, or wrap a store with your own encrypting adapter. Never commit the token file.

## Limits

- Accounting scope only: no Payments API, webhooks, reports, attachments, CDC or batch.
- The fake supports only what this kit uses (a minimal `select * from X where field = 'v'` dialect; create, sparse update and read for six entity types). Passing against it does not prove behavior against the real API.
- Fixtures and examples are invented. The minor version is pinned to 75; check Intuit's changelog before relying on newer fields.
- Issues are triaged occasionally.
